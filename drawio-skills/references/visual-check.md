# 视觉自检规范（L3）

结构 lint 只能抓机械问题（重复 ID、悬空边、重叠）。**布局难看、标签截断、连线穿模**这类问题必须靠"看图"发现。本规范定义怎么做看图这一步。

## 何时必须做视觉自检

- 任何交付给他人看的图（架构评审、汇报、文档配图）
- 使用 `layout=free` 手工坐标的图
- 节点数超过 10 的图
- 生成后 lint 有 WARN 的图（WARN 往往是视觉问题的前兆）

## 标准流程

### 1. 生成草稿 PNG（不带 -e）

```bash
drawio -x -f png --width 2000 -o _draft.png diagram.drawio
```

**关键**：草稿**绝对不要加 `-e`**（`--embed-diagram`）。带内嵌 XML 的 PNG 会被多数视觉模型直接拒收，看不了图。

### 2. 读草稿图，按清单检查

按以下顺序逐项看，发现一项记一项：

| 检查项 | 典型症状 | 修复方式 |
|--------|----------|----------|
| 节点重叠 | 两个框叠在一起、文字互相压 | 调 layer 或节点顺序，重新生成 |
| 标签截断 | 文字末尾消失、出现省略号 | 加大节点 `w`/`h`，或缩短 label |
| 连线穿模 | 箭头从节点中间穿过 | 减少跨层边、调整节点位置 |
| 边堆叠 | 多条线完全重合，看不出条数 | 给边加 label 错开，或拆分节点 |
| 文字过小 | 需要凑近才能看清 | fontSize 提到 12 以上 |
| 分组错位 | 分组标题和内容对不上 | 检查 group 归属，重新生成 |
| 留白过多 | 图只占画布一小块 | 减少页面尺寸或用 --crop |
| 颜色混乱 | 同类节点颜色不一致 | 回到 role 语义，统一用 preset |

### 3. 修复（最多 2 轮）

- **结构性修复**：改 JSON spec，重新 `build_diagram.py` 生成。这是首选。
- **局部微调**：只动 drawio XML 里对应 cell 的坐标/尺寸，不要整张重画。
- **上限 2 轮**：两轮后仍有明显问题，说明模式选错了或节点太多，应该拆图，而不是继续调坐标。

### 4. 导出最终文件

确认视觉无误后再导出正式交付物：

```bash
# 可编辑 PNG（带内嵌 XML，打开 PNG 能还原成图）
drawio -x -f png -e -s 2 -o diagram.drawio.png diagram.drawio

# SVG / PDF
drawio -x -f svg -e --embed-svg-images -o diagram.svg diagram.drawio
drawio -x -f pdf -e -o diagram.pdf diagram.drawio
```

最终检查：`validate.py` 必须 ERROR=0。

## 没有视觉模型 / 无法看图时的降级方案

如果当前环境不能读 PNG，改用 DOM 几何核验——直接读渲染后的坐标，比"用眼睛猜"更可靠：

1. 用浏览器打开 `https://app.diagrams.net/?...#R<压缩内容>`（或用 `--dump-dom` 拿渲染 DOM）。
2. 提取每条边的 `<path>` 段和 label 锚点坐标。
3. 检查：path 是否穿过无关的 `<rect>` 包围盒；label 锚点是否在节点框内。
4. 这类检查能发现"连线穿模""标签落在错误节点上"这类纯视觉模型也会漏的几何缺陷。

## 常见陷阱（血泪经验）

- **不要反复重画**： agent 常见失控行为是"画完→截图→发现瑕疵→清空重画"，循环不停。规则是：一次生成、一次看图、定点修复，最多两轮。
- **草稿别 embed**：再说一次，`-e` 的 PNG 视觉模型拒收。
- **导出退出码不可信**：draw.io 桌面版是 GUI 程序，命令行调用时常立刻返回 0 但没写出文件。导出后要确认文件存在且非空。
- **黑描边 + 浅色填充是 linlan 签名**：视觉自检时不要把"留白多、描边黑"当成缺陷去修——那是刻意的风格。
